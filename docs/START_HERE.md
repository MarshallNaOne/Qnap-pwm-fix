# Начните здесь

Этот документ предназначен для человека, который не участвовал в исходном
расследовании и не обязан знать внутреннее устройство QNAP.

## Коротко: что было не так

В QNAP TS-230 штатный 80-мм вентилятор заменили на ARCTIC P8 Slim PWM PST,
способный вращаться примерно до 3000 RPM. Точная модель снятого вентилятора в
ходе исходной работы не была записана. После замены QTS продолжил применять к
новому вентилятору пределы профиля штатной конфигурации. В интерфейсе выбрали
100 %, но фактически вентилятор вращался только около 2200 RPM.

Сам вентилятор был исправен. Значение 100 % в интерфейсе означало не 100 %
электрического PWM, а 100 % диапазона, разрешённого профилем модели QNAP.

В профиле находилось:

```ini
MAX_PWM = 178
```

PWM представлен числом от 0 до 255. Поэтому реальная верхняя граница была:

```text
178 / 255 × 100 % = 69.8 %
```

После изменения верхней границы на 255 вентилятор достиг 2970 RPM.

Исправление нужно не для постоянного шума и работы на максимуме. Оно возвращает
доступ ко всему диапазону нового вентилятора, чтобы у QTS оставался запас
охлаждения при высокой температуре или нагрузке. Подробное объяснение:
[`PROBLEM.md`](PROBLEM.md).

## Что именно меняет решение

Решение не устанавливает постоянные обороты и не заменяет алгоритм QTS. Оно
меняет только верхнюю границу диапазона:

```text
до:    QTS может выбирать значения от MIN_PWM до 178
после: QTS может выбирать значения от MIN_PWM до 255
```

После применения Smart Fan, температурные пороги, ручной процент, контроль
ошибок вентилятора и аварийные режимы остаются в ведении QTS.

## Почему нужен QPKG

Файл `/etc/model.conf` создаётся QTS при загрузке и указывает на конкретный
профиль модели. Ручная правка работает сразу, но может исчезнуть после reboot
или обновления прошивки.

QPKG — штатный формат приложения QNAP. Пакет `QNAP-PWM` запускает маленький
service script при старте системы. Скрипт:

1. ждёт появления `/etc/model.conf`;
2. проверяет точное имя профиля;
3. проверяет, что вентилятор управляется MCU и имеет ожидаемое назначение;
4. допускает только исходное значение 178 или уже применённое 255;
5. заменяет 178 на 255;
6. кратковременно вызывает штатный HAL override;
7. снимает override, возвращая управление QTS;
8. записывает каждое действие в журнал.

## Какой способ выбрать

### Вариант A: сначала только диагностика

Подходит, если вы не уверены в модели или хотите проверить систему без
изменений:

```sh
sh scripts/qnap-ts230-fan-cap.sh
```

Без аргументов helper только читает файлы.

### Вариант B: разовая ручная проверка

Подходит для доказательства причины до установки пакета:

```sh
sudo sh scripts/qnap-ts230-fan-cap.sh --apply-255
```

Затем в QTS примените 50 %, подождите около 10 секунд, примените 100 % и
подождите 20–30 секунд. Если причина та же, скорость приблизится к 3000 RPM.

Подробности: [`MANUAL_METHOD.md`](MANUAL_METHOD.md).

### Вариант C: постоянное решение

Установите через App Center:

```text
release/QNAP-PWM_1.0.0.qpkg
```

Пакет неподписанный, поэтому QTS покажет предупреждение. Перед установкой
сверьте SHA-256:

```text
fafb44ea03a43520cd5f1bbe69ddd333986e992a1448a43b7cdfe6a096aa2293
```

Полная инструкция: [`QPKG.md`](QPKG.md).

## Минимальная безопасная проверка перед изменением

Выполняйте по SSH:

```sh
uname -a
uname -m
getcfg System Model -f /etc/config/uLinux.conf
readlink -f /etc/model.conf
grep -n -A6 '^\[System FAN\]' /etc/model.conf
cat /etc/config/qfan.conf
```

Для исследованного NAS ожидается:

```text
architecture: aarch64
internal model: TS-XA28A
/etc/model.conf -> /etc/model_Q04Z0_Q0500_10_10.conf
FAN_UNIT = MCU
FAN_1 = I1:C0
MIN_PWM = 51
MAX_PWM = 178
HEAT_SOURCE = SYS, DISK
```

Если профиль, `FAN_UNIT`, `FAN_1` или исходное значение отличаются, не
подгоняйте команды механически. Сначала повторите диагностику.

## Что означает каждая важная сущность

### QTS

Операционная система и интерфейс QNAP. Пользователь выбирает Smart Fan или
фиксированную скорость через QTS.

### QFan

Политика температур и скоростей. `/etc/config/qfan.conf` содержал
`high_pwm=255`, поэтому этот файл не был источником ограничения.

### HAL

Hardware Abstraction Layer QNAP. Он переводит режим QTS в команды конкретному
железу. Процесс называется `hal_daemon`, а события ему отправляет `hal_event`.

### MCU

Микроконтроллер платы QNAP, через который в этой модели управляется системный
вентилятор. Именно поэтому прямой Linux PWM sysfs оказался неактивным путём.

### PWM

Широтно-импульсное управление скоростью вентилятора. В конфигурации QNAP
диапазон задаётся целыми числами 0–255.

### RPM

Фактические обороты в минуту. PWM и RPM не обязаны быть строго линейными, но
соотношение 178/255 хорошо согласовалось с наблюдением 2200/3000 RPM.

### QPKG

Установочный и сервисный формат QNAP. Это не пакет `opkg`: похожее написание
часто вызывает путаницу. В этом проекте готовый файл имеет расширение `.qpkg`.

## Что доказано, а что ещё нет

Доказано:

* ручная замена 178 → 255 даёт 2970 RPM;
* переключение GUI заставляет QTS применить новый предел;
* цикл HAL `force level 7 → clear` также применяет новый предел;
* после `clear` управление возвращается QTS;
* service script меняет 178 → 255 и пишет успешный журнал;
* QPKG 1.0.0 был установлен App Center и зарегистрирован как enabled;
* QTS запустил service script во время установки.

Не было зафиксировано в исходной сессии:

* успешное автоматическое выполнение настоящего QPKG после холодного старта;
* поведение после обновления QTS;
* установка текущей пересобранной версии из `release/`, содержащей усиленные
  проверки профиля.

Эти пункты не замалчиваются: сценарий проверки приведён в `QPKG.md`.

## Чего делать не нужно

Не записывайте значения напрямую в:

```text
/sys/class/pwm/pwmchip0/*
/sys/devices/platform/980070d0.pwm/*
```

Наблюдаемые каналы не менялись вслед за GUI, а Device Tree помечал
`rtk_fan` как disabled. Эти каналы могут относиться к другой периферии.

Также не нужно:

* держать `fan_level=7` постоянно;
* останавливать или перезапускать `hal_daemon`;
* вызывать неизвестные функции `libuLinux_hal.so` через самодельный ABI;
* вручную регистрировать приложение в `qpkg.conf`;
* пытаться обходить code signing через случайные значения CLI;
* считать резервную копию в `/etc` гарантированно persistent.

## Рекомендуемый порядок для нового NAS

1. Сохранить вывод read-only диагностики.
2. Убедиться в точном профиле и секции вентилятора.
3. Создать backup за пределами временного `/etc`, если требуется долгосрочное
   хранение.
4. Выполнить разовую ручную проверку 178 → 255.
5. Зафиксировать RPM и температуры до/после.
6. Вернуть 178 или перезагрузить систему, если тест не подтвердился.
7. Только после подтверждения установить QPKG.
8. Проверить запуск пакета вручную через QPKG subsystem.
9. Выполнить контролируемый reboot.
10. Повторять проверку после каждого обновления QTS.
