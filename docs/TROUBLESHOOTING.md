# Диагностика проблем

## Сначала соберите единый отчёт

```sh
echo '===== SYSTEM ====='
date
uname -a
getcfg System Model -f /etc/config/uLinux.conf

echo '===== MODEL LINK ====='
ls -l /etc/model.conf
readlink -f /etc/model.conf

echo '===== SYSTEM FAN ====='
grep -n -A8 '^\[System FAN\]' /etc/model.conf

echo '===== QPKG STATUS ====='
sudo /sbin/qpkg_cli --status QNAP-PWM --output 2

echo '===== QPKG CONFIG ====='
sudo grep -n -A30 '^\[QNAP-PWM\]' /mnt/HDA_ROOT/.config/qpkg.conf

echo '===== PACKAGE FILES ====='
sudo ls -la /share/CACHEDEV1_DATA/.qpkg/QNAP-PWM 2>&1

echo '===== PACKAGE LOG ====='
sudo cat /mnt/HDA_ROOT/.config/qnap-pwm.log 2>&1

echo '===== HAL ====='
pidof hal_daemon
```

## Пакет не виден в App Center

Проверьте, что установлен именно `.qpkg`, а не каталог исходников, `.zip` или
файл `.md5`.

Правильный файл:

```text
release/QNAP-PWM_1.0.0.qpkg
```

Для неподписанного пакета используйте `Install Manually`. Простой
`qpkg_cli -m` на исследованном QTS прекращал работу на code-signing pre-check.

## QTS сообщает «отсутствует цифровая подпись»

Это ожидаемо: проект не имеет подписи QNAP. Сверьте SHA-256 и подтверждайте
только файл из доверенного репозитория.

Если хэш не совпадает, не устанавливайте пакет.

## Статус `notfound`

```json
{"status_value":"notfound","st_code":5}
```

Возможные причины:

* CLI только распознал пакет, но code-signing остановил установку;
* App Center не завершил установку;
* вручную созданная секция не считается установленным QPKG;
* пакет удалён.

Проверьте `/var/log/log.qpkg` и наличие секции `[QNAP-PWM]`.

## Статус `disabled` и `Incomplete_Conf = 1`

Это характерно для старой ручной регистрации. Не исправляйте её добавлением
случайных полей. Сделайте backup `qpkg.conf`, удалите только старую секцию и
установите настоящий QPKG через App Center.

Перед любым удалением секции обязательно проверьте соседние заголовки. Никогда
не применяйте диапазонный `sed`, скопированный из старого лога, если порядок
секций изменился.

## Пакет enabled, но `MAX_PWM` остался 178

Проверьте журнал. Возможные сообщения:

### `model.conf did not appear after 60 seconds`

QPKG стартовал слишком рано или QTS не создал профиль. Проверьте boot и цель
симлинка. Не увеличивайте timeout без понимания причины.

### `unexpected model config`

QTS использует другой профиль. Это защитное срабатывание. Не заменяйте
`EXPECTED_CONF` только для подавления ошибки: сначала сравните секцию и
аппаратный путь.

### `[System FAN] section not found`

Формат профиля изменился. Вероятна новая версия QTS или другая модель.

### `FAN_UNIT is not MCU`

На этой системе другой backend. Этот QPKG применять нельзя.

### `unexpected FAN_1 mapping`

Аппаратное назначение отличается от исследованного `I1:C0`. Нужна новая
диагностика.

### `unexpected MAX_PWM`

Скрипт разрешает только 178 и 255. Любое третье значение может означать другую
ревизию профиля или вмешательство другого ПО.

## `MAX_PWM=255`, но RPM не выросли

Проверьте последовательно:

1. Какой режим выбран в QTS.
2. Выполнен ли HAL reload.
3. Снят ли forced mode.
4. Не ограничивает ли `qfan.conf` значение `high_pwm`.
5. Есть ли тахометрический сигнал и корректно ли он читается.
6. Способен ли конкретный вентилятор физически достичь ожидаемых RPM.

Ручное применение:

```sh
sudo /sbin/hal_event --se_set_fan_force_speed fan_level=7
sleep 3
sudo /sbin/hal_event --se_clear_fan_force_speed
```

## Обороты застряли около 2800 после тестов

Возможно, остался forced mode. Выполните:

```sh
sudo /sbin/hal_event --se_clear_fan_force_speed
```

Затем повторно примените выбранный режим в QTS.

## Обороты колеблются во время `fan_level=7`

Такое наблюдалось в исходном эксперименте. Forced level — внутренний режим,
не финальное значение. Главное, чтобы после `clear` вернулась политика QTS.

## После reboot снова 178

Если QPKG отсутствует или disabled, это ожидаемо: QTS пересоздал `/etc`.

Если QPKG enabled, изучите свежий журнал. Для чистого теста перед reboot
сохраните и очистите лог, как описано в `QPKG.md`.

## После обновления QTS пакет перестал работать

Не пытайтесь немедленно ослабить проверки. Снимите:

```sh
readlink -f /etc/model.conf
grep -n -A10 '^\[System FAN\]' /etc/model.conf
sudo /sbin/qpkg_cli --status QNAP-PWM --output 2
sudo tail -100 /mnt/HDA_ROOT/.config/qnap-pwm.log
```

Сравните новый профиль с задокументированным. Обновление могло изменить путь,
формат или принцип управления.

## `qbuild --create-env`: Permission denied

Вы пытаетесь создавать проект внутри установленного QDK. Создавайте его на
data volume в каталоге, принадлежащем вашему пользователю.

## `qbuild --strict`: `arm_64: empty directory`

Для shell-only пакета не указывайте архитектуру и удалите пустые каталоги,
созданные шаблоном. Используйте generic build.

## `qbuild --query` выводит пустые метаданные

Проверьте пакет через `qbuild --extract`. В исходном исследовании query QDK
2.3.11 был пустым, хотя извлечённые `qpkg.cfg`, `qinstall.sh` и data archive
были корректными.

## Сборка на macOS создаёт странный пакет

QDK написан под QTS/Linux и ожидает GNU-поведение некоторых программ. При
попытке нативной сборки на macOS отличались `sed`, `tar`, пути утилит и
добавлялись extended attributes.

Используйте:

```sh
sh scripts/build-qpkg-docker.sh
```

## Безопасное удаление пакета

Удаляйте через App Center. После удаления текущий профиль может оставаться со
значением 255 до reboot, потому что `stop` намеренно не меняет скорость резко.

Если нужен немедленный откат, восстановите backup или выполните точную замену
255 → 178 и HAL force/clear.

## Когда остановиться

Не продолжайте автоматическое применение, если:

* модель или профиль не совпадают;
* отсутствует backup;
* вентилятор не имеет корректного тахосигнала;
* QTS сообщает hardware/fan failure;
* температуры растут неожиданно;
* `hal_daemon` не запущен;
* после force не удаётся выполнить clear;
* конфигурация содержит неизвестный MAX_PWM.
