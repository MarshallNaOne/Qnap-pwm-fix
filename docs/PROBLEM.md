# Исходная проблема: зачем вообще понадобился этот проект

## Что изменили в NAS

В QNAP TS-230 заменили штатный корпусной вентилятор на **ARCTIC P8 Slim PWM
PST 80 mm**. Новый вентилятор — четырёхконтактный PWM-вентилятор с заявленным
диапазоном до 3000 RPM.

Точная маркировка и паспортные обороты снятого штатного вентилятора в исходной
SSH-сессии не были записаны. Поэтому документация намеренно не приписывает ему
неподтверждённую модель или скорость. Существенный факт другой: QTS продолжил
применять аппаратный профиль, рассчитанный QNAP для штатной комплектации, уже к
новому вентилятору с другим рабочим диапазоном.

## Как проявлялась проблема

В QTS был выбран фиксированный режим **100%**. Конфигурация подтверждала выбор:

```ini
FAN action = Fixed
FAN speed = 100
```

Однако GUI показывал только около **2200 RPM**, хотя ARCTIC рассчитан примерно
на **3000 RPM**. Это было важно не ради постоянной работы на максимуме, а чтобы:

* получить весь доступный запас охлаждения в жару, при высокой нагрузке или
  восстановлении RAID;
* не вводить администратора в заблуждение надписью «100%», когда физический
  управляющий сигнал ограничен ниже максимума;
* сохранить штатную автоматику QTS, контроль температуры и тахометра;
* понять причину до любых опасных записей в PWM-регистры SoC.

## Почему замена вентилятора обнаружила скрытый предел

QTS использует несколько уровней настроек. Пользовательский процент и значения
из `qfan.conf` проходят через QNAP HAL, который учитывает профиль конкретной
модели NAS. В исследованном TS-230 профиль содержал:

```ini
[System FAN]
FAN_UNIT = MCU
FAN_1 = I1:C0
MIN_PWM = 51
MAX_PWM = 178
HEAT_SOURCE = SYS, DISK
```

Шкала PWM — 0…255. Поэтому верхняя граница составляла:

```text
178 / 255 = 69.8%
```

Иными словами, **100% в GUI означало 100% разрешённого моделью диапазона, а не
255/255 на физическом пути управления**. Для нового вентилятора это давало
примерно 2200 RPM. Соотношение `2200 / 3000 ≈ 73%` достаточно близко к
`178 / 255 ≈ 70%`; точной линейности между PWM и RPM быть не обязано.

## Что сделали и что получили

Верхний предел изменили с 178 на 255. После повторного применения в GUI режима
50%, а затем 100%, QTS показал **2970 RPM**. Это подтвердило одновременно:

1. вентилятор способен выйти почти на паспортный максимум;
2. ограничение находилось в профиле QNAP, а не в `qfan.conf` и не в самом
   ARCTIC;
3. менять драйвер, Device Tree или аппаратные PWM-регистры не требуется;
4. QTS продолжает управлять вентилятором — расширяется только допустимый верх.

## Чего этот проект не делает

Проект не заставляет вентилятор всегда работать на 3000 RPM и не отключает
Smart Fan. Он меняет только `MAX_PWM` модели. Конкретное значение внутри нового
диапазона по-прежнему выбирает QTS.

Файл модели пересоздаётся при загрузке, поэтому для постоянного применения
подготовлен осторожный QPKG. Его скрипт проверяет модель, путь, секцию и исходные
значения, делает резервную копию и отказывается работать при несовпадении.
